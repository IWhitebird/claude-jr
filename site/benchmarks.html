SWE-bench Verified

All 500 tasks of SWE-bench Verified with Opus, and a fixed random sample of 100 with Sonnet, scored with the official harness (bench/swe/run.py):

model resolved cost a task
Opus 5.5 467 of 500 (93.4%) $67.32 13 cents, 34 s
Sonnet 5.5 88 of 100 (88%) $5.06 5 cents, 14 s

(Time is the median.)

Of the 33 tasks Opus did not resolve, four (psf__requests-1724, -1766, -1921, -2317) fail on this machine with the reference fix as well, so they could not have been scored as resolved here; they are counted as failures all the same. Without them it is 467 of 496 (94.2%). One task ran into the 25-minute limit; its patch passed and it counts as resolved, but its cost is missing from the total. The run was made in two sittings with builds a few days apart, same prompt and tools. This is not a leaderboard entry. The tasks are public and old enough that the models may have seen them. Each task ran once, in the task's own container, with no retries and no hints.

No agent resolves all 500. For scale, the best score on Vals.ai's independent leaderboard was 97.0% when it was last updated (1 September 2026), with a different agent and other models. All 33 of our misses produced a patch and finished normally; apart from the four above, they are fixes that did not satisfy the hidden tests.

Handing work out: when it pays

The same main agent (Opus 5.5) was given ten independent pieces of work three ways: do it all itself, give each piece to a subagent, or give each to a claude-jr worker over MCP, as Claude Code would. Subagents and workers ran on Haiku 5.5, each in its own worktree. Every arrangement fixed everything. One run of each (bench/workers/run.py):

Ten small fixes time cost
alone 22 s $0.12
with subagents 42 s $0.19
with workers 39 s $0.18
Sixty fixes, in ten packages time cost
alone 39 s $0.22
with subagents 76 s $0.32
with workers 77 s $0.34

On jobs this small, one agent doing everything is faster and cheaper. Opus edits many files in one reply, while handing the work out means writing ten briefs, waiting, and merging ten branches. The workers themselves cost 0.4 cents each and held 12.7 MB between them. Whether it pays on long tasks, where one agent's context would keep growing, has not been measured yet.

Windows

New in 0.3.0. The Windows build is 2.05 MB (claudejr-windows-x86_64.exe). Every change is built and tested on a Windows machine (bench/windows.sh): a run with tools in Git Bash and in PowerShell, a session that continues, background tasks started, merged and cancelled, the installer (which must refuse a download that fails its checksum) and --update replacing the program while it runs.

On that machine a run of 20 commands peaked at 8.2 MB, and the MCP server waiting for calls held 5.8 MB (1.2 MB of it its own; the rest is Windows' shared libraries, which every program is charged for). Those are working-set figures, Windows' counterpart of the Linux numbers above; there is no idle trim on Windows, and the interactive UI has not been measured there.
