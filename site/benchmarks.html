The release binary is built by build.sh: optimised for size, with Rust's standard library rebuilt the same way. On Linux, whenever claude-jr goes quiet it hands the pages of its own program file back to the kernel (src/sys/mem.rs), which is why it idles in less memory than its own size; they come back from the page cache as they're needed. The conversation is kept in the session file rather than in memory: each request reads the saved messages straight from it (src/store/session.rs), so a long session needs no more memory than a short one.

SWE-bench Verified

All 500 tasks of SWE-bench Verified with Opus, and a fixed random sample of 100 with Sonnet, scored with the official harness (bench/swe/run.py):

model tasks resolved cost median time per task
claude-opus-5-5 all 500 467 (93.4%) $67.32 (13 cents a task) 34 s
claude-sonnet-5-5 100 88 (88%) $5.06 (5 cents a task) 14 s

Of the 33 tasks Opus did not resolve, four (psf__requests-1724, -1766, -1921, -2317) fail on this machine with the reference fix as well, so they could not have been scored as resolved here; they are counted as failures all the same. Without them it is 467 of 496 (94.2%). One task ran into the 25-minute limit; its patch passed and it counts as resolved, but its cost is missing from the total. The run was made in two sittings with builds a few days apart, same prompt and tools. This is not a leaderboard entry. The tasks are public and old enough that the models may have seen them. Each task ran once, in the task's own container, with no retries and no hints.

Handing work out: when it pays

The same main agent (Opus 5.5) was given ten independent pieces of work in one repository three ways: do it all itself; give each piece to a subagent; give each to a claude-jr worker over MCP, as Claude Code would. Subagents and workers ran on Haiku 5.5, each in its own worktree. Two sizes: ten one-line fixes, and ten packages of six fixes each. One run of each (bench/workers/run.py):

ten small fixes ten packages (60 fixes)
fixed time cost fixed time cost
alone 10/10 22 s $0.12 60/60 39 s $0.22
with subagents 10/10 42 s $0.19 60/60 76 s $0.32
with workers 10/10 39 s $0.18 60/60 77 s $0.34

On work of this size, doing it alone wins on both counts. Opus reads and edits many files in one reply, so sixty small fixes take it a handful of requests; handing them out means writing ten briefs, waiting, and merging ten branches, and that organising is what costs. The ten workers together cost 4 cents of the $0.34 (0.4 cents each) and held 12.7 MB between them, the 22 processes of the run included.

So this does not show handing work out to be cheaper, and the numbers above should not be read that way. What it does show is that the workers themselves are nearly free; whether delegation pays depends on the pieces being long enough (many steps each, where one agent's context would grow with every step) to be worth a brief and a merge. That case has not been measured here yet.

Windows

The Windows build is 2.03 MB (claudejr-windows-x86_64.exe). CI builds it on a Windows machine, runs the 283 unit tests that apply there, and puts the binary through bench/windows.sh against the fake API: a run with tools in Git Bash and in PowerShell, a session that continues, and background tasks started, merged and cancelled, the installer (which must refuse a download that fails its checksum) and --update replacing the program while it runs.

On that machine a run of 20 commands peaked at 8.2 MB, and the MCP server waiting for calls held 5.8 MB (1.2 MB of it its own; the rest is Windows' shared libraries, which every program is charged for). Those are working-set figures, Windows' counterpart of the Linux numbers above; there is no idle trim on Windows, and the interactive UI has not been measured there.

Evals

python3 bench/evals/run.py frontend --budget 2          # 10 frontend tasks
python3 bench/evals/run.py frontend --model claude-sonnet-5-5
python3 bench/evals/run.py polyglot-python --limit 10   # Aider's polyglot benchmark
python3 bench/evals/run.py frontend --agent claude-code # the same tasks with Claude Code
python3 bench/evals/run.py frontend --dry-run           # check the runner, free

frontend/ has 10 tasks: semantic HTML, form accessibility, a responsive grid, dark mode, a cart bug, relative dates, form validation, debounce, safe HTML rendering, and a pricing page built from a design image. JS tasks are graded by hidden tests; every check was verified to fail on the starting files and pass on a correct solution. --budget stops before a task that would likely go over.
