A coding agent for the terminal, in a 2 MB binary.

claude-jr, or Claude Junior, is a small alternative to Claude Code: it reads your code, edits files and runs commands, asking before anything changes. It is written in Rust with no runtime, so it starts in 4 ms and sits in 0.7 MB of memory: about 180 times less disk and 200 times less memory than Claude Code. On SWE-bench Verified it resolved 467 of 500 tasks.

Linux, macOS curl -fsSL https://claudejr.iwhitebird.com/install | sh
Windows irm https://claudejr.iwhitebird.com/install.ps1 | iex
Docker, 3.5 MB docker run --rm -it -e ANTHROPIC_API_KEY -v "$PWD:/work" ghcr.io/iwhitebird/claude-jr

x86 and ARM; Windows in PowerShell, 64-bit Intel or AMD. Also through Homebrew and Cargo. Then run claudejr and paste an Anthropic API key, or start it with a local model: claudejr -m ollama/qwen3.

Small enough not to notice

There is no Node or Python to install and nothing running in the background. Memory stays under 4 MB however long a session runs, because the conversation is kept on disk. A whole working session, including the commands it runs, fits in a 16 MB container on a twentieth of a CPU core.

And it gets the work done

SWE-bench Verified gives an agent 500 real GitHub issues from projects like Django, sympy and scikit-learn, and checks each fix with the project's own hidden tests. claude-jr ran all of them with Claude Opus 5.5, one attempt each.

How it stays small

Nothing clever, mostly things left out.

  1. The conversation lives on disk.Every message is appended to the session file as it happens. Memory keeps only where each one is, and a request is streamed straight from the file, so a session with 8 MB of history uses the same 4 MB as a short one.
  2. No runtime underneath.One static binary, with nothing to start before it: no JavaScript engine to load and no garbage collector holding on to memory.
  3. Nothing runs while it waits.A few plain threads that sleep until you press a key or the model answers: zero CPU when idle.
  4. Unused memory goes back.When it goes quiet on Linux it hands back the parts of the program it isn't using, which is how a working agent settles at 0.7 MB.

Made to run many at once

Because each one is so small, the limit on how many you run is your API rate limit, not your machine. Background tasks each get a git worktree and branch of their own, so they can't touch each other's files or yours, and a group of them can share one budget.

492 MBbetween all of them
0.1 sto start 40 tasks
1.2 MBMCP server, idle

claudejr install claude-code (or cursor, or codex) lets your main agent start these workers itself. Whether handing work out pays depends on the work: on small jobs, one agent doing everything was faster and cheaper in our own test.

What's in it

  • -m provider/model

    Any model

    Claude by default. OpenAI, Gemini, Groq, OpenRouter, or a local model in Ollama, LM Studio or llama.cpp.

  • shift+tab

    Permission modes

    From asking about everything to an auto mode where a small model reviews each command before it runs.

  • --sandbox

    A sandbox

    On Linux it can only write to your project. Keys, sockets and the rest of your home stay out of reach.

  • task · fleet

    Background tasks

    Runs that carry on without you, each on a branch of its own, with a shared budget and a log of every step.

  • install claude-code

    Workers for other agents

    Claude Code, Cursor or Codex start workers over MCP, then read, merge or drop what each one did.

  • in parallel

    Subagents

    Side tasks go to agents that work in parallel and report back, in worktrees of their own when they change files.

  • /rewind · -c

    Rewind and resume

    Go back to before any message with its file changes undone. Every session is saved as it goes.

  • .claude/skills

    Skills and MCP

    Reads the skills you already have and talks to MCP servers, local or remote.

  • ctrl+v

    Images and the web

    Paste or drag in a screenshot. It searches and fetches pages when the task needs them.

  • ctrl+s

    A stash

    Put a half-written message aside, send another, and get the first one back afterwards.

  • # a note

    Notes that last

    Start a message with # and it is remembered for this project in every later session.

  • -p

    Scripting

    One prompt, then exit, with JSON output and a spending limit, for scripts and CI.

Questions

Is this made by Anthropic?

No. claude-jr is an independent, MIT-licensed project. It talks to Claude through Anthropic's public API, the same way any program can.

What do I need to run it?

An API key from Anthropic, or from another provider it knows (OpenAI, Gemini, Groq, OpenRouter and others), or a model running locally in Ollama, LM Studio or llama.cpp, which needs no key at all. A Claude subscription login is not supported; it uses API keys.

What does it leave out, to be this small?

Plugins, hooks, IDE integration, and the breadth of a product with a team behind it. It has the working core: tools, permissions, subagents, skills, MCP, sessions, a sandbox. If you depend on one of the missing things, Claude Code is the right tool.

Where does my code go?

To the model provider you chose, and nowhere else. claude-jr has no telemetry and no account. Beyond that it contacts only MCP servers you set up yourself, and GitHub when you ask it to --update.

Why 93.4% on SWE-bench, and not 100%?

Nobody is at 100%. The best score on an independent leaderboard was 97% when it was last updated, in September 2026. Each task gets one attempt here, with no retries. Of our 33 misses, four fail on our test machine even with the benchmark's own reference fix; the other 29 are fixes that did not satisfy the hidden tests.

Can I check the numbers?

Yes. Every figure on this page comes from a script in the repository's bench folder, most of them runnable without an API key, and the benchmarks page says how each was measured, including the ones that didn't go our way.
