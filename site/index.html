A coding agent for the terminal, in a 2 MB binary.

claude-jr, or Claude Junior, is a small alternative to Claude Code: it reads your code, edits files and runs commands, asking before anything changes. It is written in Rust with no runtime, so it starts in 5 ms and sits in 0.7 MB of memory: about 180 times less disk and 200 times less memory than Claude Code. On SWE-bench Verified it resolved 467 of 500 tasks.

Linux, macOS curl -fsSL https://claudejr.iwhitebird.com/install | sh

x86 and ARM; on Windows, inside WSL. Then run claudejr and paste an Anthropic API key, or start it with a local model: claudejr -m ollama/qwen3.

Small enough not to notice

There is no Node or Python to install and nothing running in the background. Memory stays under 4 MB however long a session runs, because the conversation is kept on disk. A whole working session, including the commands it runs, fits in a 16 MB container on a twentieth of a CPU core.

How it stays small

Nothing clever, mostly things left out.

  1. The conversation lives on disk.Every message is appended to the session file as it happens. Memory keeps only where each one is, and a request is streamed to the API straight from that file. A session with 8 MB of history uses the same 4 MB as a short one.
  2. No runtime underneath.One static binary, with nothing to start before it. There is no JavaScript engine to load and no garbage collector holding on to memory.
  3. Threads instead of an async framework.It talks to one model at a time, so a few plain threads and channels do the job, and they sleep in the kernel while waiting: zero CPU when idle.
  4. A short, fixed prompt.About 3,000 tokens with its tools, and the history only ever grows, so the provider's prompt cache stays valid from the first request to the last.
  5. Unused pages go back.When it goes quiet on Linux it hands the program pages it isn't using back to the system, which is how a working agent settles at 0.7 MB.

Made to run many at once

Because each one is so small, the limit on how many you run is your API rate limit, not your machine. Background tasks each get a git worktree and branch of their own, so they can't touch each other's files or yours, and a group of them can share one budget.

claudejr install claude-code (or cursor, or codex) lets your main agent start these workers itself. Whether handing work out pays depends on the work: on small jobs one agent doing everything was faster in our own test, and we say so.

What's in it

Any model
Claude by default; OpenAI, Gemini, Groq, OpenRouter, Ollama and other local servers with -m provider/model.
Permission modes
From asking about everything to an auto mode where a small model reviews each command. shift tab switches.
A sandbox
With --sandbox on Linux it can only write to your project; keys, sockets and the rest of your home stay out of reach.
Tasks and fleets
Runs carry on in the background, each on its own branch, with a log of every step. claudejr fleet runs a whole list.
Workers for other agents
An MCP server through which Claude Code, Cursor or Codex start workers, then read, merge or drop what each one did.
Subagents
Side tasks go to agents that work in parallel and report back, in worktrees of their own when they change files.
Rewind and resume
Go back to before any message with its file changes undone. Every session is saved as it goes.
Skills and MCP
Reads your .claude/skills and talks to MCP servers, local or remote.
Images and the web
Drag in a screenshot, and it can search and fetch pages when the task needs them.
Scripting
claudejr -p "…" runs one prompt, with JSON output and a spending limit for CI.

Questions

Is this made by Anthropic?

No. claude-jr is an independent, MIT-licensed project. It talks to Claude through Anthropic's public API, the same way any program can.

What do I need to run it?

An API key from Anthropic, or from another provider it knows (OpenAI, Gemini, Groq, OpenRouter and others), or a model running locally in Ollama, LM Studio or llama.cpp, which needs no key at all. A Claude subscription login is not supported; it uses API keys.

What does it leave out, to be this small?

Plugins, hooks, IDE integration, and the breadth of a product with a team behind it. It has the working core: tools, permissions, subagents, skills, MCP, sessions, a sandbox. If you depend on one of the missing things, Claude Code is the right tool.

Where does my code go?

To the model provider you chose, and nowhere else. claude-jr has no telemetry and no account. Beyond that it contacts only MCP servers you set up yourself, and GitHub when you ask it to --update.

Can I check the numbers?

Yes. Every figure on this page comes from a script in the repository's bench folder, most of them runnable without an API key, and the benchmarks page says how each was measured, including the ones that didn't go our way.
